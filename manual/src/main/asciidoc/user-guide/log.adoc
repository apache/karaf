=== Log

Apache Karaf provides a very dynamic and powerful logging system.

It supports:

* the OSGi Log Service
* the Apache Log4j v1 and v2 framework
* the Apache Commons Logging framework
* the Logback framework
* the SLF4J framework
* the native Java Util Logging framework

It means that applications can use any logging framework, Apache Karaf will use the central log system to manage the
loggers, appenders, etc.

==== Configuration files

By default, Apache Karaf uses Pax Logging with the Apache Log4j v2 backend (`pax-logging-log4j2`).
The initial log configuration is loaded from `etc/org.ops4j.pax.logging.cfg`.

This file uses the https://logging.apache.org/log4j/2.x/manual/configuration.html#properties[Log4j 2 properties configuration format].

You find the different Log4j 2 elements:

* loggers
* appenders
* layouts
* filters

You can add your own initial configuration directly in the file.

The default configuration defines the `rootLogger` with `INFO` log level, using the `RollingFile` file appender and the `PaxOsgi` appender.
You can change the log level to any valid Log4j 2 value (from the most to least verbose): TRACE, DEBUG, INFO, WARN, ERROR, FATAL, OFF.

The `PaxOsgi` appender is a special appender that sends log events to the OSGi Log Service (used by the `log:*` shell commands).

A `Console` appender is pre-configured, with a `ThresholdFilter` controlled by the `karaf.log.console` property (`OFF` by default, or `ALL` when running `bin/karaf run`).
This appender allows you to display log messages directly to standard output, which is useful when running Apache Karaf in server or container mode (without a local interactive console).

The `RollingFile` appender is the default file appender. It's a rolling random-access file appender that rotates log files of 16MB each.
The log files are located in `data/log/karaf.log` (`${karaf.log}/karaf.log`) by default.

The `Routing` (sift) appender is not enabled by default. This appender allows you to have one log file per deployed bundle.
By default, the log file name format uses the bundle symbolic name (in the `data/log` folder). To enable it, uncomment `log4j2.rootLogger.appenderRef.Sift.ref = Routing` and the `log4j2.appender.routing.*` properties.

You can edit this file at runtime: any change will be reloaded and be effective immediately (no need to restart Apache Karaf).

Another configuration file is used by Apache Karaf: `etc/org.apache.karaf.log.cfg`. This file configures the Log Service
used by the log commands (see later).

==== Log4j v2 XML configuration

If you prefer an external Log4j 2 XML configuration file instead of properties in `etc/org.ops4j.pax.logging.cfg`, you can:

. Edit `etc/org.ops4j.pax.logging.cfg` configuration file and set `org.ops4j.pax.logging.log4j2.config.file=${karaf.etc}/log4j2.xml`
. Add the `etc/log4j2.xml` configuration file.

A default configuration in `etc/log4j2.xml` could be:

----
<?xml version="1.0" encoding="UTF-8"?>
<Configuration status="INFO">
    <Appenders>
        <Console name="console" target="SYSTEM_OUT">
            <PatternLayout pattern="%d{ABSOLUTE} | %-5.5p | %-16.16t | %-32.32c{1} | %X{bundle.id} - %X{bundle.name} - %X{bundle.version} | %m%n"/>
        </Console>
        <RollingFile name="out" fileName="${karaf.log}/karaf.log"
              append="true" filePattern="${karaf.log}/$${date:yyyy-MM}/karaf-%d{MM-dd-yyyy}-%i.log.gz">
           <PatternLayout>
             <Pattern>%d{ABSOLUTE} | %-5.5p | %-16.16t | %-32.32c{1} | %X{bundle.id} - %X{bundle.name} - %X{bundle.version} | %m%n</Pattern>
           </PatternLayout>
           <Policies>
                <TimeBasedTriggeringPolicy />
                <SizeBasedTriggeringPolicy size="250 MB"/>
            </Policies>
        </RollingFile>
        <PaxOsgi name="paxosgi" filter="VmLogAppender"/>
    </Appenders>
    <Loggers>
        <Root level="INFO">
            <AppenderRef ref="console"/>
            <AppenderRef ref="out"/>
            <AppenderRef ref="paxosgi"/>
        </Root>
    </Loggers>
</Configuration>
----

==== Logback support

XML-based configurations for Logback are supported.
To use Logback you have to:

. Edit `etc/startup.properties` to replace the `pax-logging-log4j2` bundle line with `mvn\:org.ops4j.pax.logging/pax-logging-logback/x.x.x = 8` (where `x.x.x` is the `pax-logging` version in `etc/startup.properties`).
. Ensure the `pax-logging-logback` jar file is present in `system/org/ops4j/pax/logging/pax-logging-logback/x.x.x/pax-logging-logback-x.x.x.jar`.
. Alternatively to steps 1 and 2, when building a custom distribution with `karaf-maven-plugin`, you can configure `framework-logback`:
----
<configuration>
    <framework>framework-logback</framework>
</configuration>
----
. Edit `etc/org.ops4j.pax.logging.cfg` configuration file and replace the Log4j 2 configuration with `org.ops4j.pax.logging.logback.config.file = ${karaf.etc}/logback.xml`
. Add the `etc/logback.xml` configuration file. You need to add a `PaxAppenderDelegate` to your configuration and include it in `root`:
----
  <appender class="org.ops4j.pax.logging.logback.internal.bridges.PaxAppenderDelegate" name="VmLogAppender"/>
  <root level="INFO">
    <appender-ref ref="VmLogAppender"/>
    {...}
  </root>
----


==== `karaf.log.console` property

Before Karaf starts _proper_ logging facilities (pax-logging), it may configure `java.util.logging`. Standard
Java logging is used initially by the `Main` class and `org.apache.karaf.main.lock.Lock` implementations.
In order to configure the logging level, please set the system property `karaf.log.console` to one of the standard JUL
levels:

* `SEVERE` (highest value)
* `WARNING`
* `INFO`
* `CONFIG`
* `FINE`
* `FINER`
* `FINEST` (lowest value)

Additionally, de-facto standard log4j(2) levels can be used:

* `TRACE`
* `DEBUG`
* `INFO`
* `WARN`
* `ERROR`
* `OFF`
* `DEFAULT`

And because `org.ops4j.pax.logging` PID uses `karaf.log.console` property, it's in fact better to use log4j levels instead:

[source,options="nowrap"]
----
log4j2.rootLogger.appenderRef.Console.filter.threshold.level = ${karaf.log.console:-OFF}
----

For example, setting `karaf.log.console` to `INFO` (or lower) will turn on these logs when starting Karaf:

[source,options="nowrap"]
----
Jul 04, 2017 7:53:18 AM org.apache.karaf.main.Main launch
INFO: Installing and starting initial bundles
Jul 04, 2017 7:53:18 AM org.apache.karaf.main.Main launch
INFO: All initial bundles installed and set to start
...
----

==== Apache Karaf Light logging

The Apache Karaf Light distribution (`apache-karaf-light`) does not use Pax Logging: it uses the `framework-light` framework, which provides a lightweight, single-bundle logging service (`org.apache.karaf.services.logging`) built on top of standard `java.util.logging` (JUL).

In a single bundle at start level 8, `org.apache.karaf.services.logging` exports and implements the standard logging APIs used across OSGi and enterprise libraries:

* *OSGi Log Service R7* (`org.osgi.service.log` 1.5): registers `LogService`, `LoggerFactory`, and `LogReaderService` in the OSGi service registry.
* *SLF4J 2.x and 1.7.x* (`org.slf4j` 2.0.17 and 1.7.36): provides both an SLF4J 2 `SLF4JServiceProvider` and an SLF4J 1.7 `StaticLoggerBinder` bridging directly to JUL.
* *Apache Commons Logging* (`org.apache.commons.logging` 1.2): provides a `LogFactory` bridging to JUL.
* *Java Util Logging* (`java.util.logging`): configures the root JUL logger, console handler, and rotating file handler.

It is configured via the `etc/org.apache.karaf.logging.cfg` file (PID `org.apache.karaf.logging`):

[source,properties,options="nowrap"]
----
# Root log level (TRACE, DEBUG, INFO, WARN, ERROR, OFF)
level = INFO

# Console output threshold (TRACE, DEBUG, INFO, WARN, ERROR, OFF)
console = ${karaf.log.console:-OFF}

# File output (default values)
#file = ${karaf.log}/karaf.log
#file.maxSize = 10MB
#file.maxBackupIndex = 5

# Logger levels (logger.<name> = <level>)
#logger.org.apache.aries.blueprint = WARN
----

The supported configuration properties in `etc/org.apache.karaf.logging.cfg` are:

[cols="1,1,3"]
|===
|Property |Default |Description

|`level` (or `log.level`, `rootLogger.level`) |`INFO` (or system property `karaf.log.level`) |The root logger level. Accepts both Log4j/SLF4J level names (`TRACE`, `DEBUG`, `INFO`, `WARN`, `ERROR`, `OFF`, `ALL`) and JUL level names (`FINEST`, `FINER`, `FINE`, `CONFIG`, `INFO`, `WARNING`, `SEVERE`).
|`console` (or `console.level`) |`${karaf.log.console:-OFF}` |The threshold level for standard output console logging (`OFF` by default in interactive shell mode, `ALL` when running `bin/karaf run`).
|`file` |`${karaf.log}/karaf.log` |The path to the log file. Set to `OFF` or empty to disable file logging.
|`file.maxSize` |`10MB` |Maximum size of the log file before rotation. Supports `KB`, `MB`, and `GB` suffixes (or a raw byte count).
|`file.maxBackupIndex` |`5` |Maximum number of rotated log files to retain. When `karaf.log` reaches `file.maxSize`, it is rotated to `karaf.log.1` (and existing backups are shifted up to `karaf.log.<file.maxBackupIndex>`).
|`logger.<name>` (or `logger.<name>.level`) | |Sets the log level for the specific logger `<name>` (for example `logger.org.apache.aries.blueprint = WARN`).
|===

Property values in `etc/org.apache.karaf.logging.cfg` support `${property:-default}` system property interpolation. When OSGi ConfigurationAdmin is active, `org.apache.karaf.services.logging` registers a `ManagedService` for the `org.apache.karaf.logging` PID, so any change to `etc/org.apache.karaf.logging.cfg` (or via `config:*` shell commands) is applied dynamically at runtime without restarting Karaf.

As the `log` feature requires Pax Logging, the `log:*` commands and the JMX `LogMBean` are not available in Apache Karaf Light: log levels are managed through `etc/org.apache.karaf.logging.cfg` (or the `config:*` commands), and log entries are written to `${karaf.log}/karaf.log`.

You can also use the light logging service in your own custom distribution by configuring `<framework>framework-light</framework>` (or `static-framework-light`) in the `karaf-maven-plugin` configuration. As the framework KAR also contains Pax Logging, blacklist the Pax Logging bundles and exclude `etc/org.ops4j.pax.logging.cfg` and `system/org/ops4j/pax/logging` from the assembly (see <<_light_distribution_example,Light Distribution Example>> in the developer guide):

[source,xml,options="nowrap"]
----
<framework>framework-light</framework>
<blacklistedBundles>
    <bundle>mvn:org.ops4j.pax.logging/*</bundle>
</blacklistedBundles>
----

==== Commands

Instead of changing the `etc/org.ops4j.pax.logging.cfg` file, Apache Karaf provides a set of commands allowing to
dynamically change the log configuration and see the log content:

===== `log:clear`

The `log:clear` command clears the log entries.

===== `log:display`

The `log:display` command displays the log entries.

By default, it displays the log entries of the `rootLogger`:

----
karaf@root()> log:display
2015-07-01 19:12:46,208 | INFO  | FelixStartLevel  | SecurityUtils                    | 16 - org.apache.sshd.core - 0.12.0 | BouncyCastle not registered, using the default JCE provider
2015-07-01 19:12:47,368 | INFO  | FelixStartLevel  | core                             | 68 - org.apache.aries.jmx.core - 1.1.1 | Starting JMX OSGi agent
----

You can also display the log entries from a specific logger, using the `logger` argument:

----
karaf@root()> log:display ssh
2015-07-01 19:12:46,208 | INFO  | FelixStartLevel  | SecurityUtils                    | 16 - org.apache.sshd.core - 0.12.0 | BouncyCastle not registered, using the default JCE provider
----

By default, all log entries will be displayed. It could be very long if your Apache Karaf container is running since a long time.
You can limit the number of entries to display using the `-n` option:

#

----

By default, each log level is displayed with a different color: ERROR/FATAL are in red, DEBUG in purple, INFO in cyan, etc.
You can disable the coloring using the `--no-color` option.

The log entries format pattern doesn't use the conversion pattern defined in `etc/org.ops4j.pax.logging.cfg` file.
By default, it uses the `pattern` property defined in `etc/org.apache.karaf.log.cfg`.

----
#
# The pattern used to format the log statement when using log:display. This pattern is according
# to the log4j layout. You can override this parameter at runtime using log:display with -p.
#
pattern = %d{ISO8601} | %-5.5p | %-16.16t | %-32.32c{1} | %X{bundle.id} - %X{bundle.name} - %X{bundle.version} | %m%n
----

----

===== `log:exception-display`

The `log:exception-display` command displays the last occurred exception.

As for `log:display` command, the `log:exception-display` command uses the `rootLogger` by default, but you can
specify a logger with the `logger` argument.

===== `log:get`

The `log:get` command show the current log level of a logger.

By default, the log level showed is the one from the root logger:

----
karaf@root()> log:get
Logger | Level
--------------
ROOT   | INFO
----

You can specify a particular logger using the `logger` argument:

----
karaf@root()> log:get ssh
Logger | Level
--------------
ssh    | INFO
----

The `logger` argument accepts the `ALL` keyword to display the log level of all loggers (as a list).

For instance, if you have defined your own logger in `etc/org.ops4j.pax.logging.cfg` file like this:

----
log4j2.logger.my.name = my.logger
log4j2.logger.my.level = DEBUG
----

you can see the list of loggers with the corresponding log level:

----
karaf@root()> log:get ALL
Logger                   | Level
--------------------------------
ROOT                     | INFO
audit                    | TRACE
my.logger                | DEBUG
org.apache.aries.spifly  | WARN
org.apache.sshd          | INFO
----

The `log:list` command is an alias to `log:get ALL`.

===== `log:log`

The `log:log` command allows you to manually add a message in the log. It's interesting when you create Apache Karaf
scripts:

----
karaf@root()> log:log "Hello World"
karaf@root()> log:display
2015-07-01 07:20:16,544 | INFO  | Local user karaf | command                          | 59 - org.apache.karaf.log.command - 4.0.0 | Hello World
----

By default, the log level is INFO, but you can specify a different log level using the `-l` option:

----
karaf@root()> log:log -l ERROR "Hello World"
karaf@root()> log:display
2015-07-01 07:21:38,902 | ERROR | Local user karaf | command                          | 59 - org.apache.karaf.log.command - 4.0.0 | Hello World
----

===== `log:set`

The `log:set` command sets the log level of a logger.

By default, it changes the log level of the `rootLogger`:

----
karaf@root()> log:set DEBUG
karaf@root()> log:get
Logger | Level
--------------
ROOT   | DEBUG
----

You can specify a particular logger using the `logger` argument, after the `level` one:

----
karaf@root()> log:set INFO my.logger
karaf@root()> log:get my.logger
Logger    | Level
-----------------
my.logger | INFO
----

The `level` argument accepts any Log4j 2 log level: TRACE, DEBUG, INFO, WARN, ERROR, FATAL, OFF.

It also accepts the `DEFAULT` special keyword.

The purpose of the `DEFAULT` keyword is to delete the explicit level of the logger (keeping any other properties such as appender references) in order to inherit the level of the logger's parent (loggers are hierarchical):

----
karaf@root()> log:set DEFAULT my.logger.custom
----

It's not possible to use the `DEFAULT` keyword with the `rootLogger` as it doesn't have a parent.

===== `log:tail`

The `log:tail` is exactly the same as `log:display` but it continuously displays the log entries.

You can use the same options and arguments as for the `log:display` command.

By default, it displays the entries from the `rootLogger`:

==== JMX LogMBean

All actions that you can perform with the `log:*` command can be performed using the LogMBean.

The LogMBean object name is `org.apache.karaf:type=log,name=*`.

===== Attributes

* `Level` attribute is the level of the ROOT logger.

===== Operations

* `getLevel(logger)` to get the log level of a specific logger. As this operation supports the ALL keyword, it returns a Map with the level of each logger.
* `setLevel(level, logger)` to set the log level of a specific logger. This operation supports the DEFAULT keyword as for the `log:set` command.

==== Advanced configuration

===== Filters

You can use Log4j 2 filters on an appender, logger, or appender reference. Filters allow log events to be evaluated to determine if or how they should be published.

Common Log4j 2 filters include:

* `ThresholdFilter`: filters log events below a specified threshold level (for example, as used on the `Console` appender reference in `etc/org.ops4j.pax.logging.cfg`).
* `LevelRangeFilter`: filters log events outside a minimum (`minLevel`) and maximum (`maxLevel`) level range.
* `RegexFilter`: filters log events matching a regular expression (`regex`).

The filter can be defined directly on an appender or appender reference in `etc/org.ops4j.pax.logging.cfg`:

----
log4j2.appender.[appender-name].filter.[filter-name].type = [FilterType]
log4j2.appender.[appender-name].filter.[filter-name].[option] = [value]
----

For instance, to configure a `ThresholdFilter` on the `RollingFile` appender:

----
log4j2.appender.rolling.filter.threshold.type = ThresholdFilter
log4j2.appender.rolling.filter.threshold.level = DEBUG
----

===== OSGi specific MDC attributes

The `Routing` (sift) appender is an OSGi-oriented appender allowing you to split the log events based on MDC (Mapped Diagnostic Context) attributes.

MDC allows you to distinguish the different sources of log events.

Pax Logging provides OSGi-oriented MDC attributes by default:

* `bundle.id` is the bundle ID
* `bundle.name` is the bundle symbolic name
* `bundle.version` is the bundle version

You can use these MDC properties in `etc/org.ops4j.pax.logging.cfg` to create a log file per bundle:

----
log4j2.rootLogger.appenderRef.Sift.ref = Routing

log4j2.appender.routing.type = Routing
log4j2.appender.routing.name = Routing
log4j2.appender.routing.routes.type = Routes
log4j2.appender.routing.routes.pattern = \$\$\\\{ctx:bundle.name\}
log4j2.appender.routing.routes.bundle.type = Route
log4j2.appender.routing.routes.bundle.appender.type = RollingRandomAccessFile
log4j2.appender.routing.routes.bundle.appender.name = Bundle-\$\\\{ctx:bundle.name\}
log4j2.appender.routing.routes.bundle.appender.fileName = ${karaf.log}/bundle-\$\\\{ctx:bundle.name\}.log
log4j2.appender.routing.routes.bundle.appender.filePattern = ${karaf.log}/bundle-\$\\\{ctx:bundle.name\}.log.%i
log4j2.appender.routing.routes.bundle.appender.append = true
log4j2.appender.routing.routes.bundle.appender.layout.type = PatternLayout
log4j2.appender.routing.routes.bundle.appender.layout.pattern = ${log4j2.pattern}
log4j2.appender.routing.routes.bundle.appender.policies.type = Policies
log4j2.appender.routing.routes.bundle.appender.policies.size.type = SizeBasedTriggeringPolicy
log4j2.appender.routing.routes.bundle.appender.policies.size.size = 8MB
----

===== Enhanced OSGi stack trace renderer

By default, Apache Karaf provides a special stack trace renderer, adding some OSGi specific information.

In the stack trace, in addition of the class throwing the exception, you can find a pattern `[id:name:version]` at the
end of each stack trace line, where:

* `id` is the bundle ID
* `name` is the bundle name
* `version` is the bundle version

It's very helpful to diagnosing the source of an issue.

For instance, in the following IllegalArgumentException stack trace, we can see the OSGi details about the source of the exception:

----
java.lang.IllegalArgumentException: Command not found:  *:foo

===== Custom appenders

You can use your own appenders in Apache Karaf:

* By implementing an OSGi `org.ops4j.pax.logging.spi.PaxAppender` service (see https://github.com/apache/karaf/blob/main/examples/karaf-log-appender-example/README.md for an example).
* Or by packaging a Log4j 2 appender as an OSGi bundle attached as a fragment of the `org.ops4j.pax.logging.pax-logging-log4j2` bundle:

----
Bundle-SymbolicName: org.mydomain.myappender
Fragment-Host: org.ops4j.pax.logging.pax-logging-log4j2
----

Copy your fragment bundle into the Apache Karaf `system` folder (using the standard Maven directory layout `groupId/artifactId/version`), reference it in `etc/startup.properties` before `pax-logging-log4j2`, and restart Apache Karaf with a clean run.
