==== Karaf Web Container (Apache Tomcat)

Apache Karaf provides a web container simpler than Pax Web, based on an embedded Apache Tomcat (Servlet 6.1). It is
provided by the `karaf-web` feature, made of two bundles: the Servlet API, and the `org.apache.karaf.services.web`
bundle embedding Tomcat. It supports:

* the OSGi Servlet Whiteboard (`org.osgi.service.servlet`, the Jakarta Servlet version of the HTTP Whiteboard): the
  servlets, filters, listeners, resources and servlet context helpers registered as services are deployed in Tomcat.
* the Web Application Bundles (WAB): the bundles with a `Web-ContextPath` header are deployed as web applications.

----
karaf@root()> feature:install karaf-web
----

The `karaf-web` feature is shipped in the Karaf light distribution, ready to be installed.

[NOTE]
====
The `karaf-web` feature is an alternative to the Pax Web features (`http`, `http-whiteboard`, `war`, ...). Do not
install both: they use the same port by default, and their `web:*` commands have the same names.
====

===== Configuration

The web container is configured in the `etc/org.apache.karaf.services.web.cfg` file:

[cols="1,1,3"]
|===
|Property |Default |Description

|`host` |`0.0.0.0` |The address the connectors listen on.
|`http.enabled` |`true` |Enables the HTTP connector.
|`http.port` |`8181` |The port of the HTTP connector.
|`https.enabled` |`false` |Enables the HTTPS connector.
|`https.port` |`8443` |The port of the HTTPS connector.
|`https.keystore` |`${karaf.etc}/keystore` |The keystore containing the certificate of the server.
|`https.keystore.type` |`PKCS12` |The type of the keystore.
|`https.keystore.password` | |The password of the keystore.
|`https.key.alias` | |The alias of the key in the keystore, the first key by default.
|`https.key.password` | |The password of the key, the keystore password by default.
|`max.threads` |`200` |The maximum number of request processing threads of each connector.
|`session.timeout` |`30` |The session timeout, in minutes.
|`realm` |`karaf` |The JAAS realm authenticating the users of the web application bundles.
|`undeploy.timeout` |`30000` |How long, in milliseconds, the unregistration of a whiteboard service or the stop of a web
application bundle waits for its undeployment.
|===

When the configuration changes, Tomcat is restarted with the new configuration, and the contexts are deployed again.

===== Servlet Whiteboard

The whiteboard services are deployed following the OSGi Servlet Whiteboard specification, for instance with
Declarative Services:

----
@Component(service = Servlet.class)
@HttpWhiteboardServletPattern("/hello")
public class HelloServlet extends HttpServlet {

    @Override
    protected void doGet(HttpServletRequest request, HttpServletResponse response) throws IOException {
        response.getWriter().println("Hello");
    }

}
----

The `karaf-web` feature supports:

* the servlets (`osgi.http.whiteboard.servlet.pattern`, `osgi.http.whiteboard.servlet.name`, asynchronous support,
  multipart configuration and `servlet.init.*` init parameters).
* the filters (`osgi.http.whiteboard.filter.pattern`, `osgi.http.whiteboard.filter.servlet`,
  `osgi.http.whiteboard.filter.regex`, `osgi.http.whiteboard.filter.dispatcher`, asynchronous support and
  `filter.init.*` init parameters), ordered by service ranking.
* the listeners (`osgi.http.whiteboard.listener=true`): servlet context, servlet request and HTTP session listeners.
* the resources (`osgi.http.whiteboard.resource.pattern` and `osgi.http.whiteboard.resource.prefix`), read from the
  bundle registering them, or from its servlet context helper.
* the servlet context helpers (`osgi.http.whiteboard.context.name` and `osgi.http.whiteboard.context.path`), selected
  with `osgi.http.whiteboard.context.select`. A helper defines a context: its `handleSecurity` method is called before
  the filters, it provides the resources and the MIME types, and its `context.init.*` properties are the init
  parameters of the context. The `default` context is on `/`.

When several servlets use the same name or pattern in a context, the one with the highest ranking is deployed and the
others are shadowed. When several helpers use the same name or path, the one with the highest ranking wins.

The servlets and resources are added to and removed from the running context. A change of the servlet context helper,
of a filter or of a listener restarts the context: its servlets are destroyed and initialized again. The services are
deployed shortly after their registration, so that the services registered together, typically by a bundle starting,
are deployed together. The unregistration of a service waits for its undeployment, and the services of a stopping
bundle are undeployed together.

The servlets and filters run with the class loader of their bundle as thread context class loader.

The following parts of the specification are not supported: the error pages
(`osgi.http.whiteboard.servlet.errorPage`), the preprocessors, the `osgi.http.whiteboard.target` property, and the
`HttpServiceRuntime` service. The OSGi HTTP Service (`org.osgi.service.http`, based on `javax.servlet`) is not
provided.

===== Web Application Bundles

A bundle with a `Web-ContextPath` header is deployed in Tomcat on this context path, when it is active (or starting
with a lazy activation policy), and undeployed when it stops:

----
Bundle-SymbolicName: my-webapp
Web-ContextPath: /my-webapp
Bundle-ClassPath: WEB-INF/classes,WEB-INF/lib/my-library.jar
Import-Package: jakarta.servlet;version="[6,7)",jakarta.servlet.http;version="[6,7)"
----

The resources of the web application are the entries of the bundle, and its classes are loaded by the bundle class
loader. As in Tomcat, the web application is configured from:

* its `WEB-INF/web.xml` and the `META-INF/web-fragment.xml` of the libraries in `WEB-INF/lib`.
* the `@WebServlet`, `@WebFilter` and `@WebListener` annotations of the classes in `WEB-INF/classes` and in the
  libraries.
* the `ServletContainerInitializer` services of the bundle.

By default, a web application has a default servlet serving its static resources (`WEB-INF` and `META-INF` excepted),
and `index.html` and `index.htm` as welcome files.

The users of a web application with a `login-config` (`BASIC`, `FORM`, `DIGEST` or `CLIENT-CERT`) are authenticated
by the Karaf JAAS realm defined by the `realm` property, the roles being the Karaf roles. For instance, the `karaf`
user has the `admin` role by default:

----
<security-constraint>
    <web-resource-collection>
        <web-resource-name>admin</web-resource-name>
        <url-pattern>/admin/*</url-pattern>
    </web-resource-collection>
    <auth-constraint>
        <role-name>admin</role-name>
    </auth-constraint>
</security-constraint>
<login-config>
    <auth-method>BASIC</auth-method>
    <realm-name>karaf</realm-name>
</login-config>
----

When a web application is deployed, its servlet context is registered as a service, with the
`osgi.web.symbolicname`, `osgi.web.version` and `osgi.web.contextpath` properties.

When two web applications use the same context path, the one with the lowest bundle id is deployed. A web application
wins over a whiteboard context with the same path.

The following features are not supported: JSP, the deployment of WAR files (the `war:` and `webbundle:` URLs), the
resources in the `META-INF/resources` folder of the libraries, the `jakarta.annotation` annotations
(`@PostConstruct`, `@PreDestroy`, `@Resource`), and the `META-INF/context.xml` file.

===== Commands

The `web:context-list` command lists the contexts, whiteboard contexts and web application bundles:

----
karaf@root()> web:context-list
Path    | Type       | Name     | Bundle | State    | Message
--------+------------+----------+--------+----------+--------
/       | WHITEBOARD | default  |        | DEPLOYED |
/secure | WHITEBOARD | secure   |     62 | DEPLOYED |
/wab    | WAB        | test.wab |     63 | DEPLOYED |
----

The `web:servlet-list` command lists the servlets and the resources, and the `web:filter-list` command lists the
filters. They also list the whiteboard services which are not deployed, with the reason:

----
karaf@root()> web:servlet-list
Context | Name                  | Patterns               | Class                                                             | Bundle | Service | State    | Message
--------+-----------------------+------------------------+-------------------------------------------------------------------+--------+---------+----------+-----------------------------------
/       | resource-96           | /static/*, prefix:/www | org.apache.karaf.services.web.internal.whiteboard.ResourceServlet |     62 |      96 | DEPLOYED |
/       | shadowed              | /hello                 | jakarta.servlet.Servlet                                           |     62 |      94 | SHADOWED | the pattern /hello is already used
/       | my.HelloServlet       | /hello                 | my.HelloServlet                                                   |     62 |      93 | DEPLOYED |
/wab    | default               | /                      | org.apache.catalina.servlets.DefaultServlet                       |     63 |         | DEPLOYED |
----

The whiteboard services which are not deployed are also logged.
